# 夜后修复 Night Repair

夜后修复不是通用建议清单，而是一个本地优先的“记录 → 归因 → 处置 → 验证”网页 App。

## 当前实现

- 三段式导航：今天 / 记录 / 我的规律
- 成人硬闸门、特殊状态补剂闸门与 A–E / D+ 分型
- 30 秒症状入口、咖啡因近似计量、睡眠与饮食记录
- 本地红旗硬中断、归因排序、处置冲突消解
- 状态分 / 修复分、五条时间线、依从性反馈
- IndexedDB 每日记录、JSON / CSV 导出与 JSON 导入
- PWA manifest、离线缓存与 iOS 添加到主屏说明
- 睡眠呼吸、连续低落/早醒、极度困倦驾驶三条结构性安全分流
- 单变量 N-of-1 实验：执行/未执行各至少 5 次，以中位数差异晋升或撤回建议
- 按 A–E / D+ 分型调整的光照、控光、小睡与日历时间线
- 10 项结构化补剂证据卡与特殊人群内容闸门（正式发布前仍需专业复核）
- 睡眠截图本机预览与人工确认；不会上传，也不会以示例值冒充识别结果
- 浏览器通知能力检测；真正的 Web Push 仍需后端订阅服务
- 今日 / 昨日补录与同一睡眠日自动更新，避免重复记录污染趋势
- 咖啡因实时残留、睡前残留、个体截止线与近 7 次同一时段摄入落差
- 咖啡因敏感度工作参数、归因准确度反馈与可编辑日历提醒时间
- 最近 14 个独立睡眠日自动重分型，并保留 A–E / D+ 类型迁移记录
- 七日相位周报：睡眠中位数、中点中位数、最大漂移和规律日
- A / B / C / D / D+ / E 六套专项 protocol，以及夜班/轮班锚定睡眠模式
- 断记回归时使用“欢迎回来”而非断签惩罚
- 五条提醒可选择、改时间并一次保存；刷新后仍保留
- 每条提醒支持“做了 / 没做”，修复分只奖励完成项
- 连续 3 天全部无反馈时自动降为 3 条，避免提醒疲劳
- 日历仅导出已选提醒；提醒计划随 JSON 一起备份与恢复
- 咖啡因半衰期使用跨日“摄入 → 下一次实际入睡”配对学习；少于 7 组或信号弱时不改写默认值
- 在 3–7 小时候选范围内显示样本量、相关强度与置信度，并把通过门槛的参数用于后续残留和截止线估算

所有个人档案与健康记录只保存在当前浏览器。前端没有 API Key、Base URL 或模型模式设置。

## 当前边界

- 睡眠截图目前是“本机预览 + 人工确认”，尚未接入 OCR 模板识别。
- PWA 可离线使用并导出日历；主动 Web Push 尚未接入后端订阅。
- 咖啡因半衰期是行为数据推断出的工作参数，不是代谢检测或医学诊断。
- 补剂字段来自产品原型，正式上线前必须由具备资质者复核。

## 本地预览

```bash
node server.js
```

然后访问 `http://localhost:8787`。

GitHub Pages 可继续从 `main` 分支根目录发布静态文件。
