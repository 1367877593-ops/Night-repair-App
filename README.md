# 夜后修复 Night Repair

夜后修复不是通用建议清单，而是一个本地优先的“记录 → 归因 → 处置 → 验证”网页 App。

## 当前实现

- 三段式导航：今天 / 记录 / 我的规律
- 成人硬闸门、特殊状态补剂闸门与 A–E / D+ 分型
- 30 秒症状入口、咖啡因近似计量、睡眠与饮食记录
- 本地红旗硬中断、归因排序、处置冲突消解
- 状态分 / 修复分、五条时间线、依从性反馈
- IndexedDB 每日记录、JSON / CSV 导出与 JSON 导入
- PWA manifest、离线缓存与 iOS 添加到主屏说明
- 睡眠呼吸、连续低落/早醒、极度困倦驾驶三条结构性安全分流
- 单变量 N-of-1 实验：执行/未执行各至少 5 次，以中位数差异晋升或撤回建议
- 按 A–E / D+ 分型调整的光照、控光、小睡与日历时间线
- 10 项结构化补剂证据卡与特殊人群内容闸门（正式发布前仍需专业复核）
- 睡眠截图端上解析：支持五家设备文字模板、浏览器本机识别、复制文字降级与强制人工确认
- 可部署的 Cloudflare Worker Web Push：开启、同步时间、分钟级发送、关闭订阅与失效订阅清理
- 今日 / 昨日补录与同一睡眠日自动更新，避免重复记录污染趋势
- 咖啡因实时残留、睡前残留、个体截止线与近 7 次同一时段摄入落差
- 咖啡因敏感度工作参数、归因准确度反馈与可编辑日历提醒时间
- 最近 14 个独立睡眠日自动重分型，并保留 A–E / D+ 类型迁移记录
- 七日相位周报：睡眠中位数、中点中位数、最大漂移和规律日
- A / B / C / D / D+ / E 六套专项 protocol，以及夜班/轮班锚定睡眠模式
- 断记回归时使用“欢迎回来”而非断签惩罚
- 五条提醒可选择、改时间并一次保存；刷新后仍保留
- 每条提醒支持“做了 / 没做”，修复分只奖励完成项
- 连续 3 天全部无反馈时自动降为 3 条，避免提醒疲劳
- 日历仅导出已选提醒；提醒计划随 JSON 一起备份与恢复
- 咖啡因半衰期使用跨日“摄入 → 下一次实际入睡”配对学习；少于 7 组或信号弱时不改写默认值
- 在 3–7 小时候选范围内显示样本量、相关强度与置信度，并把通过门槛的参数用于后续残留和截止线估算
- N-of-1 次日回访自动读取昨日提醒的“做了 / 没做”，同一实验同一睡眠日更新而不重复计数
- 有效个人结论默认保留到时间线，无效结论默认退出；安全信号可以临时覆盖实验撤回
- 截图原图与识别文字不会保存；记录仅保留结构化字段、识别方式、置信度和图片尺寸
- 睡眠结构只与本人同一设备近 14 次记录比较；至少 5 次才建立深睡/REM 个人基线，厂商总分不参与计算
- 深睡或 REM 明显低于个人基线时才作为谨慎归因线索，并明确标注关联不等于因果
- 连续低落/早醒或 OSA 风险命中后硬切换到安全分流，不再混入普通恢复建议、咖啡因卡和日程
- 补充醒后户外光照与近期正餐事实，新增光照不足、餐后血糖波动和 D+ 相位冲突归因

所有个人档案与健康记录只保存在当前浏览器。开启 Web Push 后，Worker 只接收匿名推送地址、提醒类型与执行时间，不接收睡眠、症状、情绪、归因或补剂记录。前端不保存任何私钥。

## 当前边界

- 浏览器本机文字识别能力因平台而异；不支持时使用复制文字或人工确认，尚未接入 Workers 多模态兜底。
- PWA 可离线使用并导出日历；Web Push Worker、KV、VAPID 与前端地址均已配置，公开站点会在本次静态文件发布后启用入口。
- 咖啡因半衰期是行为数据推断出的工作参数，不是代谢检测或医学诊断。
- 补剂字段来自产品原型，正式上线前必须由具备资质者复核。

## 本地预览

```bash
node server.js
```

然后访问 `http://localhost:8787`。

GitHub Pages 可继续从 `main` 分支根目录发布静态文件。

部署说明见 [`worker/README.md`](./worker/README.md)。静态站与 Worker 分开部署，私钥只写入 Cloudflare Secret，不能提交到仓库。
